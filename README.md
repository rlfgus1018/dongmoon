# Dongmoon

출신 고등학교를 중심으로 사람과 커뮤니티를 연결하는 Django 기반 웹 애플리케이션입니다.

사용자는 학교명이나 지역으로 고등학교를 검색하고, 자신의 학교를 인증한 뒤 학교별 게시판과 방명록을 이용할 수 있습니다. 학교마다 일반 게시판과 인증 사용자 전용 게시판이 구분되어 있으며, 게시글과 댓글 신고를 처리할 수 있는 학교별 운영 기능도 포함되어 있습니다.

현재는 서비스의 핵심 기능을 구현하고 실제 운영 구조를 실험하기 위한 개인 개발 프로젝트입니다.

## 어떤 서비스인가요?

기존 동문 서비스는 이미 알고 있는 사람을 찾거나 졸업생 명부를 확인하는 데 초점이 맞춰진 경우가 많습니다.

이 프로젝트는 특정 인물을 직접 검색하는 방식보다, 출신 학교를 중심으로 사람들이 다시 모이고 이야기를 나눌 수 있는 공간을 만드는 것을 목표로 합니다.

사용자는 다음과 같은 흐름으로 서비스를 이용할 수 있습니다.

1. 학교명이나 지역으로 자신의 고등학교를 검색합니다.
2. 관심 있는 학교를 즐겨찾기에 추가합니다.
3. 재학 또는 졸업 증빙 자료를 제출해 학교 인증을 요청합니다.
4. 인증이 승인되면 해당 학교의 인증 게시판을 이용할 수 있습니다.
5. 학교별 방명록과 게시판을 통해 다른 사용자와 소통합니다.

## 주요 기능

### 학교 검색

학교명, 지역, 도로명 주소를 기준으로 국내 고등학교를 검색할 수 있습니다.

학교 상세 페이지에서는 다음 정보를 확인할 수 있습니다.

* 학교명
* 교육청 및 지원청
* 학교 소재 지역
* 지번 및 도로명 주소
* 설립 유형
* 개교일과 개교기념일
* 남녀공학 여부
* 전화번호와 홈페이지
* 폐교 및 휴교 여부

로그인한 사용자는 관심 학교를 즐겨찾기에 추가할 수 있으며, 검색 화면에서 인증한 학교와 즐겨찾기한 학교를 빠르게 확인할 수 있습니다.

### 회원과 프로필

Django 기본 인증 시스템을 이용해 회원가입, 로그인, 로그아웃 기능을 제공합니다.

마이페이지에서는 다음 정보를 관리할 수 있습니다.

* 닉네임
* 자기소개
* 프로필 이미지
* 인증 학교
* 작성한 게시글과 댓글
* 작성한 방명록
* 추천한 게시글

다른 사용자의 프로필에서도 공개된 활동 내역을 확인할 수 있습니다.

### 학교 인증

사용자는 재학생 또는 졸업생 인증을 신청할 수 있습니다.

인증을 신청할 때 학교와 인증 유형을 선택하고, 재학 또는 졸업 사실을 확인할 수 있는 증빙 파일을 제출합니다.

관리자가 요청을 승인하면 사용자 프로필에 인증 학교가 연결됩니다. 인증이 완료된 사용자는 해당 학교의 인증 게시판을 열람하고 글을 작성할 수 있습니다.

현재 인증 자료는 개발 환경의 로컬 미디어 폴더에 저장됩니다. 실제 서비스를 운영할 때는 개인정보 보호를 위해 접근 권한, 보관 기간, 암호화 및 삭제 정책을 별도로 구성해야 합니다.

### 학교별 커뮤니티

각 학교 상세 페이지에는 방명록과 게시판이 제공됩니다.

방명록은 간단한 인사나 학교와 관련된 짧은 이야기를 남기는 공간이며, 도배를 방지하기 위해 사용자당 하루에 한 번 작성할 수 있습니다.

게시판은 다음 두 종류로 구분됩니다.

* 일반 게시판
* 학교 인증 사용자 전용 게시판

게시글에는 제목과 본문을 작성할 수 있으며 이미지도 첨부할 수 있습니다. 다른 사용자는 댓글을 작성하거나 게시글을 추천할 수 있습니다.

### 신고와 콘텐츠 관리

사용자는 문제가 있는 게시글이나 댓글을 신고할 수 있습니다.

신고 사유는 다음과 같이 구분됩니다.

* 스팸 및 광고
* 욕설 및 비방
* 개인정보 노출
* 불법 또는 유해 정보
* 기타 사유

학교 운영자 또는 스태프는 학교별 관리 페이지에서 신고 내역을 확인하고 콘텐츠를 숨김, 복구 또는 삭제 처리할 수 있습니다.

숨김 처리된 게시글은 일반 사용자에게 노출되지 않지만, 작성자와 관리 권한이 있는 사용자는 확인할 수 있습니다.

### 학교 운영자

특정 사용자에게 학교 운영자 권한을 부여할 수 있습니다.

학교 운영자는 담당 학교에 한해 다음 기능을 사용할 수 있습니다.

* 게시글 신고 확인
* 댓글 신고 확인
* 콘텐츠 숨김 처리
* 숨김 콘텐츠 복구
* 신고 처리 상태 변경

전체 서비스 관리 권한과 학교별 관리 권한을 분리해, 학교 커뮤니티 단위로 운영할 수 있도록 구성했습니다.

### 유명 동문

학교별로 유명 동문 정보를 등록하고 보여줄 수 있습니다.

나무위키의 학교 문서에서 유명 동문 후보를 수집하는 Django 관리 명령도 포함되어 있습니다. 수집한 정보는 바로 공개하지 않고 후보 데이터로 저장한 뒤, 관리자가 내용을 검토해 승인하거나 반려할 수 있습니다.

필요한 경우 명령어 옵션을 통해 수집 결과를 자동으로 승인할 수도 있습니다.

크롤링 결과는 외부 문서의 형식이나 내용에 따라 부정확할 수 있으므로, 실제 공개 전 별도의 확인이 필요합니다.

## 실행 방법

### 1. 저장소 내려받기

```bash
git clone https://github.com/rlfgus1018/dongmoon.git
cd dongmoon
```

### 2. 패키지 설치하기

이 프로젝트는 Python 패키지와 가상환경 관리를 위해 `uv`를 사용합니다.

`uv`가 설치되어 있지 않다면 먼저 설치합니다.

Windows PowerShell에서는 다음 명령을 사용할 수 있습니다.

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

macOS 또는 Linux에서는 다음과 같습니다.

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

설치가 끝나면 프로젝트 의존성을 설치합니다.

```bash
uv sync
```

### 3. 환경변수 파일 만들기

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Windows 명령 프롬프트:

```bat
copy .env.example .env
```

macOS 또는 Linux:

```bash
cp .env.example .env
```

`.env` 파일의 값을 현재 개발 환경에 맞게 수정합니다.

일반적으로 다음과 같은 설정이 필요합니다.

```env
SECRET_KEY=change-me
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost
```

실제 운영 환경에서는 저장소에 포함된 기본값을 그대로 사용하지 말고, 충분히 긴 임의의 `SECRET_KEY`를 설정해야 합니다.

### 4. 데이터베이스 준비하기

```bash
uv run python manage.py migrate
```

로컬 개발 환경에서는 SQLite를 사용하므로 별도의 데이터베이스 서버를 설치하지 않아도 됩니다.

### 5. 관리자 계정 만들기

학교 인증 요청이나 유명 동문 후보를 관리하려면 Django 관리자 계정이 필요합니다.

```bash
uv run python manage.py createsuperuser
```

명령을 실행한 뒤 사용자명, 이메일, 비밀번호를 입력합니다.

### 6. 개발 서버 실행하기

```bash
uv run python manage.py runserver
```

서버가 실행되면 다음 주소로 접속합니다.

```text
http://127.0.0.1:8000
```

Django 관리자 페이지는 다음 주소에서 사용할 수 있습니다.

```text
http://127.0.0.1:8000/admin/
```

## 학교 데이터 가져오기

서비스에서 학교를 검색하려면 먼저 학교 기본 데이터를 데이터베이스에 적재해야 합니다.

```bash
uv run python manage.py import_schools "학교정보.csv"
```

Windows 경로 예시는 다음과 같습니다.

```powershell
uv run python manage.py import_schools "C:\data\high_schools.csv"
```

CSV 파일의 열 이름과 형식은 관리 명령에서 요구하는 구조와 일치해야 합니다.

데이터를 가져온 뒤 관리자 페이지나 학교 검색 화면에서 정상적으로 저장되었는지 확인합니다.

## 유명 동문 후보 수집

### 학교명으로 수집하기

```bash
uv run python manage.py crawl_namuwiki_alumni --school-name "고려대학교사범대학부속고등학교"
```

### 학교 코드로 수집하기

```bash
uv run python manage.py crawl_namuwiki_alumni --school-code "학교코드"
```

### 여러 학교를 한 번에 수집하기

```bash
uv run python manage.py crawl_namuwiki_alumni --all --limit 100
```

수집한 결과는 기본적으로 유명 동문 후보로 저장됩니다. 관리자가 후보 내용을 확인한 뒤 승인해야 실제 학교 페이지에 표시됩니다.

후보 검토 과정 없이 바로 공개 데이터로 저장하려면 `--auto-approve` 옵션을 사용합니다.

```bash
uv run python manage.py crawl_namuwiki_alumni --all --auto-approve
```

자동 승인을 사용하면 잘못된 인물이나 설명이 그대로 공개될 수 있으므로, 개발용 데이터가 아닌 경우에는 직접 검토하는 방식을 권장합니다.

## 주요 URL

| URL                            | 기능             |
| ------------------------------ | -------------- |
| `/`                            | 학교 검색 메인 화면    |
| `/schools/`                    | 학교 검색          |
| `/schools/<학교 코드>/`            | 학교 상세 페이지      |
| `/schools/<학교 코드>/moderation/` | 학교별 관리 페이지     |
| `/accounts/signup/`            | 회원가입           |
| `/accounts/login/`             | 로그인            |
| `/accounts/logout/`            | 로그아웃           |
| `/accounts/me/`                | 마이페이지          |
| `/accounts/users/<사용자 ID>/`    | 사용자 프로필        |
| `/admin/`                      | Django 관리자 페이지 |
| `/health/`                     | 서버 상태 확인       |

## 테스트와 코드 검사

전체 테스트를 실행합니다.

```bash
uv run python manage.py test
```

Ruff로 코드 스타일과 기본 오류를 검사합니다.

```bash
uv run ruff check .
```

자동으로 수정할 수 있는 항목을 함께 수정하려면 다음 명령을 사용합니다.

```bash
uv run ruff check . --fix
```

## 정적 파일 수집

배포 환경에서는 정적 파일을 한곳에 모아야 합니다.

```bash
uv run python manage.py collectstatic
```

개발 서버에서는 `DEBUG=True`인 경우 Django가 정적 파일과 미디어 파일을 직접 제공합니다.

## 배포 시 주의사항

현재 설정은 로컬 개발 환경을 기준으로 합니다.

운영 환경에 배포할 때는 최소한 다음 항목을 확인해야 합니다.

* `DEBUG=False` 설정
* 안전한 `SECRET_KEY` 사용
* 정확한 `ALLOWED_HOSTS` 지정
* HTTPS 적용
